  • 대출 상태는 단일 스냅샷입니다. 실제 ML 피처에는 과거 시점의 상태·정보 가용 시각이 필요합니다.

LESSON 01 / 10

01. SQL 실행 순서

행을 먼저 거를지, 집계한 그룹을 거를지 구분한다.

논리적 학습 순서: FROM / JOIN → WHERE → GROUP BY / 집계 → HAVING → 윈도 함수 → SELECT 출력 → DISTINCT → ORDER BY → LIMIT. 실행 계획의 실제 처리 순서와는 구분하세요.

01 / 문법 템플릿

SQL
SELECT customer_id, SUM(amount) AS total_amount
FROM transactions
WHERE status = 'settled'
GROUP BY customer_id
HAVING SUM(amount) >= 200
ORDER BY total_amount DESC, customer_id;

02 / 핵심 예제

SQL
SELECT customer_id, SUM(amount) AS total_amount
FROM transactions
WHERE status = 'settled'
GROUP BY customer_id
HAVING SUM(amount) >= 200
ORDER BY total_amount DESC, customer_id;
실행 결과 4 rows
customer_idtotal_amount
3300.00
6300.00
1200.00
2200.00
🐨 먼저 성공 거래만 모아 → 고객별로 합쳐 → 합계 200 이상만 남겨요. WHERE는 거래 한 건, HAVING은 고객 한 그룹을 검사해요.

03 / 면접 함정

  • SELECT에서 만든 별명 total_amount는 같은 단계의 WHERE/HAVING에서 쓸 수 없어요. ORDER BY에서는 사용할 수 있어요.
  • LEFT JOIN의 오른쪽 테이블 조건을 WHERE에 두면 매칭이 없는 행이 탈락할 수 있어요. 고객 전체를 보존할 조건은 ON 또는 사전 CTE에 두세요.
  • 윈도 함수는 WHERE/HAVING 뒤에 계산돼요. 순위를 거르려면 외부 SELECT가 필요해요.
PySpark로 연결하기

df.filter(...).groupBy(...).agg(...).filter(...)와 대응해요. Spark도 실제 물리 실행은 optimizer가 바꿀 수 있어요.

02. CTE vs 서브쿼리

중간 결과에 이름을 붙이거나, 다른 쿼리 안에 넣어 여러 단계 분석을 만든다.

01 / 문법 템플릿

SQL
WITH customer_totals AS (
  SELECT customer_id, SUM(amount) AS total_amount
  FROM transactions
  WHERE status = 'settled'
  GROUP BY customer_id
)
SELECT customer_id, total_amount
FROM customer_totals
WHERE total_amount >= 200
ORDER BY customer_id;

02 / 핵심 예제

SQL
WITH customer_totals AS (
  SELECT customer_id, SUM(amount) AS total_amount
  FROM transactions
  WHERE status = 'settled'
  GROUP BY customer_id
)
SELECT customer_id, total_amount
FROM customer_totals
WHERE total_amount > (SELECT AVG(total_amount) FROM customer_totals)
ORDER BY customer_id;
실행 결과 4 rows
customer_idtotal_amount
1200.00
2200.00
3300.00
6300.00
🐨 CTE는 “고객별 합계표”라는 이름표예요. 서브쿼리는 괄호 안에서 그 표의 평균을 구해요. 평균의 대상은 settled 거래가 있는 6명이며 거래 없는 2명은 제외합니다.

03 / 면접 함정

  • CTE는 영구 테이블이나 자동 캐시가 아니에요. PostgreSQL은 조건에 따라 인라인하거나 materialize합니다. 항상 더 빠르다는 답은 피하세요.
  • NOT IN의 하위 결과에 NULL이 있으면 원하지 않는 UNKNOWN이 생길 수 있어요. 부재 확인은 상관 NOT EXISTS가 명확해요.
  • 값 하나를 기대하는 스칼라 서브쿼리는 한 열·최대 한 행이어야 해요. 여러 행이면 오류예요.
PySpark로 연결하기

중간 DataFrame에 변수명을 붙이는 것과 비슷하지만, CTE를 Spark cache()/persist()와 같다고 생각하면 안 돼요.

🐨 보너스 · 선우와 코돌이의 재귀 CTE 핵심만

선우가 추천한 친구 → 그 친구가 추천한 친구 → 더 없으면 끝!

SQL
WITH RECURSIVE friends AS (
  -- First: customers referred by Seonwoo
  SELECT customer_id, name, referred_by
  FROM customers WHERE referred_by = 1
  UNION ALL
  -- Next: customers referred by the friends just found
  SELECT c.customer_id, c.name, c.referred_by
  FROM customers AS c
  JOIN friends AS f ON c.referred_by = f.customer_id
)
SELECT * FROM friends ORDER BY customer_id;

03. 집계 윈도 함수와 ROWS BETWEEN

거래 행을 유지한 채 고객별 합계·누적합·이동평균을 붙인다.

01 / 문법 템플릿

SQL
SELECT transaction_id, customer_id, amount,
       SUM(amount) OVER (
         PARTITION BY customer_id
         ORDER BY txn_date, transaction_id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_amount
FROM transactions
WHERE status = 'settled'
ORDER BY customer_id, txn_date, transaction_id;

02 / 핵심 예제

SQL
SELECT transaction_id, amount,
       SUM(amount) OVER (PARTITION BY customer_id) AS customer_total,
       SUM(amount) OVER (
         PARTITION BY customer_id ORDER BY txn_date, transaction_id
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_amount,
       ROUND(AVG(amount) OVER (
         PARTITION BY customer_id ORDER BY txn_date, transaction_id
         ROWS BETWEEN 1 PRECEDING AND CURRENT ROW
       ), 2) AS last_two_avg
FROM transactions
WHERE customer_id = 1 AND status = 'settled'
ORDER BY txn_date, transaction_id;
실행 결과 3 rows
transaction_idamountcustomer_totalrunning_amountlast_two_avg
101100.00200.00100.00100.00
102100.00200.00200.00100.00
1030.00200.00200.0050.00
🐨 GROUP BY는 거래들을 한 줄로 접어요. OVER는 원래 거래 줄을 그대로 두고 계산 결과만 옆에 붙여요. 1 PRECEDING은 “앞 거래 한 줄 + 현재 줄”, 즉 최대 두 거래입니다.

03 / 면접 함정

  • ORDER BY만 쓰면 기본 frame은 현재 행의 동점 행까지 포함하는 RANGE 방식이에요. 행별 누적합은 ROWS와 유일한 정렬 기준을 명시하세요.
  • ROWS 2 PRECEDING은 앞 2행이지 2일이 아니에요. 달력 기간은 RANGE INTERVAL 또는 날짜 집계가 필요해요.
  • SUM/AVG는 NULL을 제외합니다. 0은 포함해요. 모든 값이 NULL이면 합계도 NULL이며, 모르는 값을 무조건 0으로 바꾸면 의미가 달라져요.
PySpark로 연결하기

Window.partitionBy(...).orderBy(...).rowsBetween(Window.unboundedPreceding, Window.currentRow) + F.sum(...).over(w).

04. 랭킹 함수와 동점 처리

고객별 최신 1건, 공동 1위, 상위 N개 금액을 구한다.

01 / 문법 템플릿

SQL
WITH ranked AS (
  SELECT transaction_id, customer_id, amount,
         ROW_NUMBER() OVER (
           PARTITION BY customer_id
           ORDER BY amount DESC NULLS LAST, transaction_id
         ) AS rn
  FROM transactions
  WHERE status = 'settled'
)
SELECT transaction_id, customer_id, amount
FROM ranked
WHERE rn = 1
ORDER BY customer_id;

02 / 핵심 예제

SQL
WITH totals AS (
  SELECT customer_id, SUM(amount) AS total_amount
  FROM transactions WHERE status = 'settled'

05. LEAD / LAG

현재 거래와 직전·다음 거래를 나란히 놓고 변화량이나 간격을 구한다.

01 / 문법 템플릿

SQL
SELECT customer_id, transaction_id, amount,
       LAG(amount) OVER (
         PARTITION BY customer_id ORDER BY txn_date, transaction_id
       ) AS previous_amount
FROM transactions
WHERE status = 'settled'
ORDER BY customer_id, txn_date, transaction_id;

02 / 핵심 예제

SQL
SELECT transaction_id, txn_date, amount,
       LAG(amount) OVER w AS previous_amount,
       amount - LAG(amount) OVER w AS amount_change,
       LEAD(txn_date) OVER w - txn_date AS days_to_next
FROM transactions
WHERE customer_id = 1 AND status = 'settled'
WINDOW w AS (PARTITION BY customer_id ORDER BY txn_date, transaction_id)
ORDER BY txn_date, transaction_id;
실행 결과 3 rows
transaction_idtxn_dateamountprevious_amountamount_changedays_to_next

1022026-01-02100.00100.000.000
1032026-01-020.00100.00-100.00NULL
🐨 LAG는 “바로 앞 친구”, LEAD는 “바로 뒤 친구”예요. 날짜끼리 빼면 일수입니다. 같은 날 거래면 간격은 0일이에요.

03 / 면접 함정

  • 첫 행의 LAG는 이전 행이 없어서 NULL입니다. LAG(amount, 1, 0)의 0은 이전 행이 없을 때만 사용하고 이전 행의 NULL 금액은 바꾸지 않아요.

  • 증가율은 (현재-이전)/이전. 이전이 0이면 NULLIF로 보호하고, 정수형 데이터라면 numeric 변환이 필요해요.

07. Pivoting: CASE WHEN + 집계

채널·상태처럼 행에 있는 범주를 대시보드 열로 펼친다.

SQL
SELECT customer_id,
       SUM(CASE WHEN channel = 'card' THEN amount ELSE 0 END) AS card_amount,

FROM transactions WHERE status = 'settled'
GROUP BY customer_id
ORDER BY customer_id;

02 / 핵심 예제

SQL
SELECT customer_id,
       SUM(CASE WHEN channel = 'card' THEN amount ELSE 0 END) AS card_amount,
       SUM(CASE WHEN channel = 'transfer' THEN amount ELSE 0 END) AS transfer_amount,
       COUNT(*) FILTER (WHERE amount IS NULL) AS missing_amount_count
FROM transactions WHERE status = 'settled'
GROUP BY customer_id
ORDER BY customer_id;

🐨 “card면 카드 칸에, transfer면 이체 칸에!” 고객별로 합쳐요. 2번 고객의 transfer 금액은 미상인데 합계가 0처럼 보일 수 있어 missing_amount_count도 함께 확인합니다.

  • 빈 문자열과 NULL은 다릅니다. TRIM만 하면 공백 입력은 빈 문자열로 남아 NULLIF가 필요해요.

  • BTRIM은 기본적으로 양끝 일반 공백을 제거해요. 내부 공백·탭·잘못된 @까지 검증하지 않습니다. 형식 검증과 정제는 별도 규칙이에요.

WITH previous_dates AS (
  SELECT *, LAG(txn_date) OVER (
    PARTITION BY customer_id ORDER BY txn_date, transaction_id
  ) AS previous_date
  FROM transactions WHERE status = 'settled'
), session_starts AS (
  SELECT *, CASE WHEN previous_date IS NULL OR txn_date - previous_date > 1
                 THEN 1 ELSE 0 END AS new_session
  FROM previous_dates
), session_ids AS (
  SELECT *, SUM(new_session) OVER (
    PARTITION BY customer_id ORDER BY txn_date, transaction_id
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS session_id
  FROM session_starts
)

       MAX(txn_date) AS end_date, COUNT(*) AS txn_count,
       SUM(amount) AS known_total,
       COUNT(*) FILTER (WHERE amount IS NULL) AS missing_count
FROM session_ids
GROUP BY customer_id, session_id
ORDER BY customer_id, session_id;

말로 답하는 개념 질문 5개

CTE와 서브쿼리는 어떻게 다른가요?

CTE는 WITH로 중간 결과에 이름을 붙이고 같은 문장 안에서 참조하는 방법이고, 서브쿼리는 다른 쿼리 내부에 들어가는 SELECT입니다. 다단계 로직은 CTE로 읽기 쉽게 만들고 단일 값 비교에는 서브쿼리를 자주 사용합니다. PostgreSQL은 CTE를 인라인하거나 materialize할 수 있으므로 문법만으로 성능 우열을 단정하지 않고 EXPLAIN (ANALYZE, BUFFERS)로 확인합니다.

WHERE에서 윈도 함수를 왜 못 쓰나요?

논리적으로 WHERE가 먼저 입력 행을 거르고 그 뒤에 윈도 함수가 계산됩니다. 따라서 같은 SELECT의 WHERE에서는 순위 결과를 사용할 수 없습니다. CTE나 서브쿼리에서 순위를 만든 다음 바깥 WHERE에서 필터링합니다.

ROW_NUMBER, RANK, DENSE_RANK의 차이는요?

100, 100, 90에 대해 ROW_NUMBER는 1,2,3이고 동점 내 순서를 정할 보조키가 필요합니다. RANK는 1,1,3, DENSE_RANK는 1,1,2입니다. 정확한 행 개수인지 공동 순위인지 서로 다른 상위 금액인지 먼저 확인합니다.

ROWS와 RANGE는 어떻게 다른가요?

ROWS는 정렬된 물리적 행 개수를 기준으로 frame을 정하고, RANGE는 정렬값 범위와 peer 관계를 기준으로 합니다. 날짜가 같으면 기본 RANGE 누적합은 같은 날짜의 동점 행들을 함께 포함할 수 있습니다. 거래별 누적합은 유일한 순서와 명시적 ROWS frame을 사용합니다.

대출 모델용 SQL 피처에서 무엇을 가장 조심하나요?

출력 단위를 고객인지 대출 신청인지 먼저 정합니다. 그 예측 시점 전에 실제로 이용 가능했던 정보만 사용하고, 이후에 갱신된 status나 결과 label을 피처에 섞지 않습니다. JOIN으로 행이 늘어나는지, NULL과 무거래를 구분했는지 확인하고 기간과 집계 정의를 고정합니다.
