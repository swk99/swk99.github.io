01. 긴 SQL을 작은 조각으로 나누기

본문 번역

고급 SQL 강의에서 점점 긴 쿼리를 작성하게 되면, 코드를 더 작은 단위로 나누고 재사용할 수 있게 해 주는 공통 테이블 표현식(CTE)과 서브쿼리를 이해하는 것이 중요합니다.

CTE란 무엇인가요?

CTE는 Common Table Expression의 줄임말로, 쿼리 안에 있는 또 다른 쿼리와 같습니다. WITH 문으로 중간 결과에 이름을 붙이면 복잡한 쿼리를 더 읽기 쉽고 유지보수하기 쉽게 만들 수 있습니다. 이 결과는 주 쿼리가 실행되는 동안에만 참조할 수 있어 분석을 단계별로 정리하는 데 도움이 됩니다.

서브쿼리란 무엇인가요?

서브쿼리(내부 쿼리)는 하나의 쿼리 안에 다른 쿼리를 넣는 방법입니다. 괄호 안에 쿼리를 작성하여 주 쿼리에서 사용할 중간 결과를 만들고, 계산하거나 데이터를 필터링할 수 있습니다. 이를 통해 데이터를 더 세밀하게 다룰 수 있습니다.

🐨 코돌이의 쉬운 설명

CTE는 “중간 결과에 이름표 붙이기”, 서브쿼리는 “필요한 자리에 계산식 끼워 넣기”라고 생각하세요. 원문은 임시 테이블에 비유하지만, CTE가 실제 임시 테이블을 생성하거나 결과를 반드시 저장하는 것은 아니에요. 서브쿼리도 표뿐 아니라 값 하나를 반환할 수 있어요.

-- CTE: 먼저 이름을 붙이고 사용
WITH expensive AS (
  SELECT * FROM concerts WHERE concert_revenue > 600000
)
SELECT * FROM expensive;

-- 서브쿼리: FROM 안에 바로 넣기
SELECT *
FROM (
  SELECT * FROM concerts WHERE concert_revenue > 600000
) AS expensive;
비교CTE서브쿼리
작성 위치주 쿼리 앞의 WITHSELECT / FROM / WHERE 등 쿼리 내부
기억법이름 붙인 중간 결과괄호 안에 넣은 쿼리
참조같은 문장 안에서 이름으로 여러 번 참조해당 위치에서 사용; 상관 참조도 가능
잘 맞는 상황여러 단계 분석, 복잡한 로직, 재귀값 하나 비교, 존재 여부, 짧은 중간 계산
성능DB와 실행 계획에 따라 달라짐DB와 실행 계획에 따라 달라짐

02. CTE는 언제 사용하나요?

본문 번역

CTE와 서브쿼리는 비슷한 목표를 달성할 수 있지만, 사용하기 좋은 상황과 장점이 다릅니다.

① 복잡한 쿼리를 나눌 때

쿼리의 시작 부분에 CTE를 선언하면 분석 논리를 더 쉽게 파악할 수 있습니다. 긴 쿼리를 작고 관리하기 쉬운 구성 요소로 나누면 코드를 이해하고 유지보수하기 편해집니다.

-- CTE 시작
WITH genre_revenue_cte AS (
  SELECT genre, SUM(concert_revenue) AS total_revenue
  FROM concerts
  GROUP BY genre
)
-- CTE 끝, 주 쿼리 시작
SELECT g.genre, g.total_revenue,
       AVG(c.concert_revenue) AS avg_concert_revenue
FROM genre_revenue_cte AS g
INNER JOIN concerts AS c ON g.genre = c.genre
WHERE c.concert_revenue > g.total_revenue * 0.5
GROUP BY g.genre, g.total_revenue;
🐨 코돌이의 쉬운 설명

먼저 장르별 총매출을 구한 뒤, 개별 공연 매출이 그 장르 총매출의 50%를 넘는 공연만 남겨요. 마지막 AVG는 필터를 통과한 공연들의 평균이지 전체 장르의 평균이 아니에요. 주어진 5행 예시에서 Pop 합계는 1,850,000이라 925,000을 넘는 공연이 없고, K-Pop은 BTS만 625,000을 넘어요.

② 같은 중간 결과를 여러 번 참조할 때

큰 쿼리 안에서 같은 서브쿼리 결과가 여러 번 필요하다면 CTE로 정리할 수 있습니다. 원문은 이를 중복 계산 방지의 장점으로 소개합니다.

보충·정정 같은 SQL을 반복 작성하지 않아도 된다는 장점은 있지만, 실제 계산이 한 번만 수행된다고 보장되지는 않습니다. CTE의 인라인 처리나 결과 저장 여부는 DB와 실행 계획에 따라 달라집니다.

③ 🐨 재귀 CTE — 핵심만!

찾은 사람의 부하를 계속 찾기.

👩🏻 선우 → 🐨 코돌이 → 아기코 → 아무도 없으면 끝!

SQL Server 문법 · 선우의 직원 번호는 10이라고 할게요.

;WITH 친구들 AS (
  -- ① 선우의 부하 찾기
  SELECT * FROM employees
  WHERE manager_id = 10

  UNION ALL  -- 찾은 결과 이어 붙이기

  -- ② 방금 찾은 사람의 부하 찾기
  SELECT e.*
  FROM employees AS e
  JOIN 친구들 AS r
    ON e.manager_id = r.employee_id
)
SELECT * FROM 친구들; -- 완성된 명단 보기
🐨 핵심은 딱 한 줄!

e.manager_id = r.employee_id

새 사람의 상사 번호 = 방금 찾은 사람의 번호

03. 서브쿼리는 언제 사용하나요?

본문 번역

① WHERE에서 값 하나와 비교할 때

다른 쿼리의 결과와 단일 값을 비교하고 싶다면 WHERE 절에 서브쿼리를 넣을 수 있습니다. 서브쿼리 결과에 따라 필터 조건이 달라져 유연하게 데이터를 추출할 수 있습니다.

SELECT artist_name
FROM concerts
WHERE concert_revenue > (
  SELECT AVG(concert_revenue) FROM concerts
);
🐨 코돌이의 쉬운 설명

안쪽 쿼리가 전체 평균 매출을 구해요. 바깥 쿼리는 그 평균보다 매출이 높은 아티스트를 골라요. 예시 5행 평균은 620,000이므로 Taylor Swift와 BTS가 남아요. AVG의 정수 처리 방식은 DB에 따라 달라질 수 있지만 이 예시 평균은 정수예요.

② 계산한 열을 추가하고 집계할 때

서브쿼리로 새 열을 만들거나 큰 쿼리에서 집계에 필요한 중간 값을 구할 수 있습니다. 원래 데이터에 계산 결과를 덧붙여 더 풍부한 분석을 할 수 있습니다.

SELECT artist_name, genre, concert_revenue,
       (SELECT AVG(concert_revenue) FROM concerts) AS avg_concert_revenue,
       (SELECT MAX(concert_revenue) FROM concerts) AS max_concert_revenue
FROM concerts;
🐨 코돌이의 쉬운 설명

각 아티스트 행 옆에 전체 평균 620,000과 전체 최댓값 800,000을 붙여요. 이 두 서브쿼리는 바깥 행을 참조하지 않으므로 모든 행에 같은 값이 표시돼요. 값 하나가 필요한 위치의 서브쿼리는 한 열, 최대 한 행을 반환해야 해요.

③ IN / NOT IN / EXISTS로 필터링할 때

서브쿼리는 다른 쿼리의 조건에 따라 결과를 걸러 내기 위해 IN, NOT IN, EXISTS와 함께 자주 사용됩니다.

SELECT artist_name
FROM concerts
WHERE artist_id IN (
  SELECT artist_id
  FROM concert_revenue
  WHERE concert_revenue > 500000
);
🐨 코돌이의 쉬운 설명

안쪽에서 “매출 500,000 초과인 아티스트 ID 목록”을 만들고, 바깥에서 그 목록에 있는 아티스트를 찾아요. 이 원문 예제의 concert_revenue는 별도 테이블 이름이에요. 아래 실습에 제공된 것은 concerts뿐이므로, 이 쿼리에는 추가 테이블이 필요해요.

연산자질문주의점
IN이 값이 목록 안에 있나요?여러 행을 반환하는 서브쿼리 가능
NOT IN이 값이 목록에 없나요?목록에 NULL이 있으면 예상과 다르게 필터링될 수 있음
EXISTS조건을 만족하는 행이 하나라도 있나요?값 자체보다 행의 존재 여부를 검사

④ 상관 서브쿼리: 바깥 행에 맞춰 계산할 때

상관 서브쿼리는 바깥 쿼리의 값을 참조합니다. 두 데이터 목록을 나란히 놓고, 첫 번째 목록의 각 항목에 대해 두 번째 목록에서 그 항목에 맞는 답을 찾는다고 생각해 보세요. 두 목록이 서로 대화하면서 각 행에 맞는 세부 정보를 주고받는 것과 같습니다.

SELECT artist_name, genre, concert_revenue
FROM concerts AS c1
WHERE concert_revenue = (
  SELECT MAX(concert_revenue)
  FROM concerts AS c2
  WHERE c1.genre = c2.genre
);
🐨 코돌이의 쉬운 설명

c1과 c2는 같은 테이블의 서로 다른 별명이에요. 바깥 행이 BTS라면 안쪽은 K-Pop만 비교하고, Taylor Swift라면 Pop만 비교해요. 따라서 장르별 매출 1위가 나와요. 공동 1위도 모두 포함해요. 이는 논리적인 이해 방식이며 DB가 실제로 매 행마다 그대로 재실행한다는 뜻은 아니에요.

05. CTE와 서브쿼리로 같은 문제 풀기

본문 번역 · 원문 SQL

1단계: 멤버 1인당 매출 계산 + 장르별 순위 매기기

두 풀이 모두 공연의 멤버 1인당 매출을 계산하고, 이를 기준으로 각 장르 안에서 아티스트의 순위를 매깁니다.

풀이 1 · CTE 사용

WITH ranked_concerts_cte AS (
SELECT artist_name, concert_revenue, genre, number_of_members,
       (concert_revenue / number_of_members) AS revenue_per_member,
       RANK() OVER (
         PARTITION BY genre
         ORDER BY (concert_revenue / number_of_members) DESC
       ) AS ranked_concerts
FROM concerts
)
SELECT * FROM ranked_concerts_cte;

풀이 2 · 서브쿼리의 내부에 들어갈 쿼리

원문은 이 단계도 “서브쿼리 사용”이라고 부르지만, 아래 코드 자체는 아직 단독 SELECT입니다. 다음 단계에서 괄호로 감싸 서브쿼리로 사용합니다.

SELECT artist_name, concert_revenue, genre, number_of_members,
       (concert_revenue / number_of_members) AS revenue_per_member,
       RANK() OVER (
         PARTITION BY genre
         ORDER BY (concert_revenue / number_of_members) DESC
       ) AS ranked_concerts
FROM concerts;
구문쉬운 뜻
concert_revenue / number_of_members멤버 1인당 얼마를 벌었는지 계산
PARTITION BY genre장르별로 각각 다른 순위표 만들기
ORDER BY … DESC매출이 높은 사람부터 정렬
RANK()같은 값은 공동 순위 부여: 1, 1, 3
AS ranked_concerts계산한 순위 열에 이름 붙이기

2단계: 장르별 1위만 선택하기

CTE 또는 서브쿼리의 결과에서 순위가 1인 행만 남기면 각 장르의 최상위 아티스트를 얻을 수 있습니다.

WITH ranked_concerts_cte AS (
SELECT artist_name, concert_revenue, genre, number_of_members,
       (concert_revenue / number_of_members) AS revenue_per_member,
       RANK() OVER (
         PARTITION BY genre
         ORDER BY (concert_revenue / number_of_members) DESC
       ) AS ranked_concerts
FROM concerts
)
SELECT artist_name, concert_revenue, genre, number_of_members,
       revenue_per_member
FROM ranked_concerts_cte
WHERE ranked_concerts = 1
ORDER BY revenue_per_member DESC;
SELECT artist_name, concert_revenue, genre, number_of_members,
       revenue_per_member
FROM (
SELECT artist_name, concert_revenue, genre, number_of_members,
       (concert_revenue / number_of_members) AS revenue_per_member,
       RANK() OVER (
         PARTITION BY genre
         ORDER BY (concert_revenue / number_of_members) DESC
       ) AS ranked_concerts
FROM concerts
) AS subquery
WHERE ranked_concerts = 1
ORDER BY revenue_per_member DESC;
🐨 코돌이의 쉬운 설명

같은 SELECT 단계의 WHERE에서 방금 만든 윈도 함수 순위를 바로 필터링할 수 없어서 한 겹 감싸는 거예요. 안쪽에서 순위 만들기 → 바깥에서 1위만 남기기. CTE든 서브쿼리든 이 두 단계는 같아요. 최종 ORDER BY는 결과 표시 순서이고, OVER 안의 ORDER BY는 순위 계산 기준이에요.

보충: 원문 나눗셈의 함정

PostgreSQL과 SQL Server에서 정수 ÷ 정수는 소수 부분이 잘릴 수 있어요. 정밀도를 잃으면 다른 값이 공동 순위가 될 수도 있습니다. 실습에서는 1.0 * concert_revenue / NULLIF(number_of_members, 0)를 사용하세요. 멤버 수가 NULL이거나 0인 행은 아래 안전한 풀이처럼 제외합니다. 순위는 반올림 전 값으로 매기고, 표에 표시할 때만 반올림하세요.

소수 나눗셈과 잘못된 멤버 수를 처리한 권장 풀이
WITH revenue AS (
  SELECT artist_name, genre, concert_revenue, number_of_members,
         1.0 * concert_revenue / NULLIF(number_of_members, 0)
           AS revenue_per_member
  FROM concerts
  WHERE number_of_members > 0
), ranked AS (
  SELECT *, RANK() OVER (
    PARTITION BY genre ORDER BY revenue_per_member DESC
  ) AS artist_rank
  FROM revenue
)
SELECT artist_name, genre, concert_revenue, number_of_members,
       revenue_per_member
FROM ranked
WHERE artist_rank = 1
ORDER BY revenue_per_member DESC;

예시 5행으로 직접 따라가기

버튼을 눌러 원본 데이터가 계산 → 순위 → 필터를 거치는 모습을 확인하세요. 아래 표는 제공된 5행으로 계산한 결과이며 SQL 실행기는 아닙니다.

06. 결과 해석하기

본문 번역

결과를 보면 각 장르에서 가장 높은 성과를 거둔 아티스트를 확인할 수 있습니다.

  • Beyonce는 멤버 1명으로 750,000달러를 벌어 1인당 매출도 750,000달러이며, R&B 장르에서 1위입니다.
  • Ariana Grande는 멤버 1명으로 공연 매출 720,000달러를 기록해 Pop 장르의 1위를 차지했습니다.
  • Eminem은 멤버 1명으로 620,000달러를 벌어 Hip-Hop 장르에서 1위입니다.

입력 표와 결과 표가 다른 이유

원문에 보이는 5행은 데이터의 일부입니다. 위 결과는 더 큰 전체 데이터에 대한 원문 결과이며, 첨부 파일에는 전체 입력이 들어 있지 않습니다. 앞의 5행만 실행하면 Taylor Swift와 BTS가 나오는 것이 맞습니다.

CTE와 서브쿼리는 복잡한 SQL을 작은 부분으로 나눠 줍니다. 여러 단계의 데이터 변환이나 분석을 할 때 코드를 읽고 이해하기 쉬워집니다. 각 부분을 따로 실행해 볼 수 있으므로 문제를 찾아 수정하는 디버깅에도 유리합니다.

마지막으로 기억할 세 문장
  1. CTE는 중간 결과에 이름을 붙이고, 서브쿼리는 다른 쿼리 안에 넣는다.
  2. 순위로 필터링하려면 순위를 계산한 결과를 바깥 쿼리에서 읽는다.
  3. 가독성은 구조로 판단하고, 속도는 실제 실행 계획으로 확인한다.
